# Phase 1 Reports — What Each File Is For

Everything below is generated by `notebooks/phase1_holdings_data_state_analysis.ipynb`. Re-run the notebook after any change to `MANDATORY` or `MIN_ROWS_PER_GROUP` and every file here refreshes together.

**Current scoring setup:** 7 mandatory fields, confirmed with the Investment Office — Capital Invested, Current Cost, Unrealized Value, Realized Proceeds, Deal Status, Sector, Geographic Focus. (The IO's list also included "Public vs. Private Classification"; there is no clean source field for it, so it is handled separately — see the entity/classification section below — and is not part of the completeness score.) Funds or managers with fewer than 10 rows are reported separately as low-evidence and never ranked.

Population: 58,160 raw rows → 52,048 real investment rows after removing cash, liabilities, accounting journal entries, and subtotal lines (6,112 removed). 385 funds, 101 managers, 8,633 distinct company names, 6 reporting periods (Dec-24 through Mar-26).

---

## 1. Scorecards — completeness by dimension (the headline numbers)

| File | What it contains | Use it to |
|---|---|---|
| `data_state_by_field.csv` | Fill rate for all 329 substantive columns | Answer "which columns are unreliable across the whole book" |
| `data_state_by_fund.csv` | Completeness score for all 385 funds | Rank funds, find the worst vehicles |
| `data_state_by_manager.csv` | Completeness, row count, fund count, company count per manager (101 rows) | Rank GPs, decide who Operations contacts first |
| `data_state_by_manager_field.csv` | Field-by-field fill rate per manager | See *which* field a specific manager is missing, not just their overall score |
| `holdings_attributes.csv` | Full 837-column inventory of the raw extract | Reference list when someone asks "does the vendor even send field X" |

## 2. Conditional scorecards — the defensible version

A blank field is not always a defect. A "Current" deal is not expected to carry Realized Proceeds, so scoring it as missing overstates the gap. These files apply the Investment Office's own field-applicability rules on top of the raw fill rate.

| File | What it contains | Use it to |
|---|---|---|
| `data_state_by_fund_conditional.csv` | Fund completeness recomputed with not-applicable cells excluded, next to the unconditional score | Show the difference between "looks incomplete" and "is actually incomplete" |
| `data_state_by_manager_conditional.csv` | Same, at manager level | Same, for GP-level conversations |
| `flagged_missing_fields_conditional.csv` | 7,540 rows that are genuine gaps after removing not-applicable cells | This is the list to actually escalate, not the unconditional one |
| `flagged_missing_fields.csv` | 7,803 rows, unconditional (every blank on a mandatory field) | Superset / audit trail; larger than the conditional list because it includes fields that were never supposed to be filled |

**Headline result:** unconditional fill rate 95.6% → conditional completeness 96.8%. Funds below the 85% threshold drop from 102 to 83 once not-applicable cells are excluded — 19 funds were never actually behind, they were just being penalized for fields that don't apply to them.

## 3. Deal Status derivation & consistency checks

Deal Status can be derived independently from Unrealized Value, Realized Proceeds, and Current Cost, using the Investment Office's own definitions. This is a second, numbers-based opinion on the same field the vendor reports directly.

| File | What it contains | Use it to |
|---|---|---|
| `deal_status_conformance_exceptions.csv` | 26 rows where the reported Deal Status disagrees with what the numbers imply (all "Written Off" reported vs. "Fully Exited" derived) | **This is the file most relevant to the PDF validation side of the project.** Every row here is a candidate to check against the source PDF. |
| `consistency_rule_results.csv` | 16 internal-consistency rules (non-negative values, date ordering, accounting identities, Deal Status definitions, time-series monotonicity) with applicable-row counts and violation rates | Sanity-check the CSV on its own terms before blaming a PDF extraction step for a mismatch |

## 4. Reporting cadence & time coverage

| File | What it contains | Use it to |
|---|---|---|
| `fund_reporting_cadence.csv` | Each fund's own inferred reporting rhythm — quarterly, annual, semi-annual, or single-period | Know a fund's expected reporting calendar before flagging it as "missing" a quarter |
| `reporting_gaps_by_series.csv` | 144 fund-company series with a genuine interior gap, adjusted for each fund's own cadence (not a naive quarterly grid) | Target list for "why does this holding disappear and reappear" follow-up |

## 5. Entity resolution

| File | What it contains | Use it to |
|---|---|---|
| `source_asset_classification.csv` | Row and name counts for each of the 5 classification tiers (holding / unnamed aggregate / balance sheet / accounting entry / subtotal) | One-line summary of how the population was split |
| `source_asset_review_queue.csv` | 4 company names too generic to auto-classify (e.g. "Hero Investments") | Human sign-off queue, not a bug list |

**Not yet generated, but wired up in the notebook:**
- `source_asset_classifier_rules.csv` — guarded on a `rules_table()` function that doesn't exist yet in `source_asset_filter.py`. Skipped silently.
- `entity_resolution_candidates.csv` — needs `rapidfuzz` installed (`pip install rapidfuzz`). Without it, only exact-normalization matches are found (425 collision groups, e.g. "X.AI" vs "X.AI Holdings Corp." — printed in the notebook, not yet exported to a file).

1,107 of the 8,633 company names (12.8%) are held by more than one fund — that's the comparison set for any cross-fund valuation work.

---

**One-liner for anyone new to this folder:** the unconditional files (`data_state_by_*`) say where the gaps are; the conditional files say which of those gaps are real; the Deal Status and consistency files check whether the numbers that ARE there are internally trustworthy; everything else supports one of those three questions.
